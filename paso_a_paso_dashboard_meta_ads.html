Del mensaje inicial al dashboard funcionando

El recorrido completo: qué le dijiste a la IA, qué prompt maestro te generó, y cómo se construye con Claude Code paso a paso.

1

Hablas con la IA de forma natural

Le explicas, sin estructura ni formato de prompt, qué quieres construir. Esto es lo que le pasaste:

"Quiero que me des un prompt maestro para Claude Code para montar un dashboard para ver esto en tiempo real sin tener que descargar los ficheros xlsx. Aunque también se puedan cargar. Tal vez que se pueda elegir el portafolio y del portafolio la cuenta que necesito ver. No quiero editar nada, solo que se pueda ver. Y que seas capaz con IA de analizar lo que está pasando, las acciones a tomar y las recomendaciones en caso de que las haya, todo en tiempo real."
2

La IA convierte eso en un prompt maestro estructurado

A partir de una petición conversacional, la IA construye una especificación técnica completa: rol, restricciones innegociables, stack, fuentes de datos, filtros, análisis IA, plan de fases y criterios de aceptación. Este es el prompt que obtuviste:

Ver prompt maestro completo
Prompt maestro — Dashboard Meta Ads (solo lectura + análisis IA) 1. ROL Y OBJETIVO Eres un ingeniero full-stack senior. Vas a construir un dashboard web de solo lectura para analizar campañas de Meta Ads (Facebook/Instagram) en vivo, sin descargar informes .xlsx. El panel debe: — Conectarse a la Meta Marketing API en modo LECTURA. — Permitir elegir portafolio → cuenta publicitaria → campaña → rango de fechas. — Permitir cargar un .xlsx alternativo, parseado al mismo modelo de datos. — Mostrar KPIs, tendencias semanales, distribución por conjunto/creativo y tabla de detalle. — Ofrecer un módulo de Análisis con IA que explique qué está pasando, señale alertas y proponga acciones. — No se edita nada. Solo se visualiza. 2. RESTRICCIONES INNEGOCIABLES — Solo lectura hacia Meta: nunca POST/PUT/DELETE. — Permisos mínimos: ads_read + business_management, nunca ads_management. — Secretos server-side: token de Meta y API key de Anthropic solo en variables de entorno del servidor, nunca en el cliente. — Caché y rate limits: 5–15 min, con backoff en errores. Mostrar hora del último refresco. — Sin base de datos obligatoria: caché en memoria basta. 3. STACK Next.js (App Router) + TypeScript · Tailwind CSS · Recharts · SheetJS (xlsx) · @anthropic-ai/sdk · fetch nativo para Meta. 4. FUENTES DE DATOS 4.1 Meta Marketing API — endpoints GET: /me/businesses, /{business_id}/owned_ad_accounts y client_ad_accounts, /act_{account_id}/campaigns, /act_{account_id}/insights (con level, fields, time_increment, breakdowns). Extracción de leads: robusta frente a actions[] con action_type variable (leadgen_grouped, onsite_conversion.lead_grouped, lead, o que contenga "lead"). Coste por lead desde cost_per_action_type o spend/leads. 4.2 Carga de .xlsx — hoja "Formatted Report", cabecera en fila 2, columnas en español, forward-fill jerárquico de campaña/conjunto/anuncio, Nivel de la entrega indica el nivel. 4.3 Modelo de datos común — estructura Row unificada (source, level, campaign/adset/ad, semana, spend, impressions, reach, frequency, clicks, ctr, cpc, cpm, leads, cpl, age, gender) que alimenta gráficos y análisis IA sea cual sea la fuente. 5. SISTEMA DE FILTROS 5.1 Ámbito en cascada: Portafolio → Cuenta → Campaña (multi) → Conjunto (multi, dependiente) → Creativo (multi, dependiente). 5.2 Fechas: presets rápidos, granularidad (día/semana/mes), comparación de periodo con deltas ▲/▼ coloreados (en CPL, bajar = mejor). 5.3 Desgloses: edad, sexo, plataforma, posición, dispositivo, estado de entrega. Aviso: combinaciones de breakdowns incompatibles deben gestionarse sin romper la UI. 5.4 Umbrales: gasto mínimo, leads mínimos, CPL máximo, búsqueda por texto — filtran en cliente, instantáneos, sin gastar llamadas a la API. 5.5 UX: barra esencial siempre visible + panel de filtros avanzados en popover + chips de filtros activos + estado en la URL + botón Actualizar explícito. 5.6 Modo archivo: al cargar .xlsx se sustituye la fuente Meta y se indica visualmente. 6. MÉTRICAS Y CÁLCULOS KPIs (gasto, leads, CPL, CTR, frecuencia, clics) con deltas de comparación. Gráficos semanales, por conjunto/creativo, por edad/sexo, y señal de fatiga (frecuencia + CTR por creativo en el tiempo). Cuidado con divisiones por cero. 7. MÓDULO DE ANÁLISIS IA Ruta /api/analyze server-side que recibe el dataset agregado + filtros activos y llama a la Anthropic Messages API. Devuelve JSON con resumen, alertas (por severidad), acciones (pausar/escalar/vigilar/testear) y recomendaciones. System prompt específico del negocio (semáforo de CPL, umbrales de fatiga real, fase de aprendizaje, umbral mínimo de gasto para juzgar un creativo, audiencia que convierte, LTV como métrica final real, estructura Andromeda/ABO/CBO). 8. UI / DISEÑO Tema oscuro, estética de panel técnico. Cabecera con selectores + hora de refresco. Fila de KPIs. Pestañas: Resumen · Rendimiento · Creativos · Edad/Sexo · Análisis IA. Sin botones de edición — que se note que es solo lectura. Estados de carga, vacío y error bien cuidados. 9. CONFIGURACIÓN .env.example con META_ACCESS_TOKEN, GRAPH_API_VERSION, ANTHROPIC_API_KEY, ANTHROPIC_MODEL, CACHE_TTL_SECONDS. 10. PLAN DE CONSTRUCCIÓN POR FASES 1) Andamiaje · 2) Conexión Meta · 3) Insights + modelo de datos · 4) Gráficos y tabla · 5) Carga de xlsx · 6) Análisis IA · 7) Pulido visual · Entrega final con instrucciones de arranque y README. 11. CRITERIOS DE ACEPTACIÓN Filtros coherentes y reactivos · multi-selección funcional · deltas de comparación con color correcto · estado en URL · breakdowns incompatibles gestionados · leads/CPL coincidentes con el xlsx real · backend sin escrituras ni tokens expuestos · análisis IA con JSON válido y acciones concretas · paridad entre fuente Meta y fuente xlsx.
3

Preparas lo que necesitas antes de tocar Claude Code

  • Meta System User token con permisos ads_read + business_management (Business Manager → Usuarios del sistema). Un token de usuario normal caduca y te rompe el dashboard a los pocos días.
  • API key de Anthropic para el módulo de análisis.
  • Un .xlsx real exportado de Meta, de una cuenta y semana conocidas — lo necesitas para validar cifras más adelante.
  • Node.js instalado y una carpeta de proyecto vacía.
4

Le das el prompt a Claude Code — pero no entero de golpe

El propio prompt maestro ya lo dice: por fases. Si le pasas todo junto y le dices "hazlo", intenta construir frontend, backend y análisis IA a la vez, y descubres los errores de conexión con Meta cuando ya tienes 500 líneas de UI encima. Dale el prompt completo como contexto del proyecto, pero pídele explícitamente que empiece solo por la Fase 1.

5

Fase 1 — Andamiaje

Next.js + TypeScript + Tailwind. Layout oscuro con selectores mockeados (sin datos reales todavía). Objetivo: tener la estructura visual antes de meter datos.

6

Fase 2 — Conexión a Meta (la fase crítica)

Solo /api/meta/portfolios y /api/meta/accounts. Pídele que te enseñe el JSON de respuesta antes de seguir. Si el token o los permisos fallan, mejor descubrirlo ahora que con todo el dashboard montado encima.

7

Fase 3 — Insights y modelo de datos normalizado

Aquí vive el punto que más se rompe: la extracción de leads desde actions[], con nombres de action_type que cambian (leadgen_grouped, onsite_conversion.lead_grouped...). Pruébalo contra una cuenta real y compáralo con el .xlsx de esa misma semana antes de dar la fase por buena.

8

Fase 4 — Gráficos y tabla sobre datos reales

KPIs, tendencia semanal, distribución por conjunto/creativo, ranking, tabla de detalle. Todo alimentado por el modelo normalizado de la fase anterior — nunca por datos mockeados.

9

Fase 5 — Carga de .xlsx al mismo modelo

Aquí validas cifras cruzadas: sube el informe real y comprueba que los leads y el CPL coinciden exactamente con lo que ya viste vía API para esa cuenta y semana.

10

Fase 6 — Análisis IA

Se conecta el botón "Analizar con IA" al system prompt de negocio (semáforo de CPL, fatiga real, fase de aprendizaje, gasto mínimo para juzgar un creativo, audiencia que convierte, LTV como métrica final). Comprueba que la respuesta es JSON válido y que las acciones son concretas, no genéricas.

11

Fase 7 — Pulido visual

Ajustes finales de estética sobre el tema oscuro y la referencia de diseño que le pasaste. Es la última fase, no la primera — pulir antes de tener datos reales es tiempo perdido.

12

Checklist final antes de dar por cerrado el dashboard

  • Cambiar cualquier filtro actualiza los datos correctamente; umbral/búsqueda son instantáneos y no re-piden a Meta.
  • Multi-selección de campaña/conjunto/creativo permite comparar más de uno.
  • Comparación de periodo con deltas de color correcto (en CPL, bajar = verde).
  • El estado de los filtros vive en la URL.
  • Breakdowns incompatibles dan aviso claro, no error crudo.
  • Leads y CPL coinciden exactamente con el .xlsx de la misma cuenta y semana.
  • El backend nunca escribe a Meta ni expone tokens al cliente.
  • El análisis IA devuelve JSON válido y acciones concretas.
  • El dashboard funciona igual con datos en vivo que con .xlsx cargado.
Nota: si además quieres que retome el resumen estructurado y la crítica del proyecto IA Business Lab con los documentos del proyecto, dímelo y lo hago aparte.
